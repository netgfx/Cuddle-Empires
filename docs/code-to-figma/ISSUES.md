# Code → Figma: issues met and how they were solved

Running log from the first full migration of the Cuddle Empires UI (2026-10-15). Each entry: symptom → cause → fix (and where the fix lives).

| # | Symptom | Cause | Fix |
|---|---------|-------|-----|
| 1 | `generate_figma_design` capture script never returned (Playwright hung 5 min) | `window.figma.captureForDesign()` keeps its toolbar alive and its promise does not settle after a successful submit | `capture.mjs` races it against a 45 s timer; completion is confirmed by polling `generate_figma_design` with the captureId |
| 2 | Captured layers lost the current-player tint, chip rings and the striped card backs | The capture serialiser does not evaluate `color-mix()` or `repeating-linear-gradient()` | Captures are used as a layout reference only; tokens pre-compute every `color-mix()` per team / continent (`extract-tokens.mjs`) and stripes are rebuilt in the library |
| 3 | Capture had no variables although `bindVariables=true` | The CSS custom properties live on `.ui-root`, not `:root`, and most colours are literals | Variables come from `extract-tokens.mjs` instead of the capture |
| 4 | `createPage` → "The Starter plan only comes with 3 pages" | Starter plan limit | 3 pages: 📐 Library, 🖥 Screens, 🔎 Reference captures; boards and sections organise content inside them |
| 5 | `addMode` → "Limited to 1 modes only" | Starter plan: one mode per variable collection | Team / continent / breakpoint values are separate variables (`team/Azure/tint-18`, `layout/tablet/icon-btn`); `retint()` in `_lib.js` rebinds a subtree from one team to another. On Professional+ fold them into modes (see README) |
| 6 | View seat: read tools (`get_metadata`, `get_screenshot`, `get_design_context`…) capped at ~20 calls / month | Figma MCP rate limits by seat | All reads and screenshots go through `use_figma` (`node.screenshot()`, scripted inspections), which is a write tool and not rate limited the same way |
| 7 | Every variant of Badge showed "3"; the Placeholder input showed "Lena" | A TEXT component property has one default for the whole set; binding fixed-content variants to it overrides their text | Only bind text that really varies; fixed glyphs (✓, !, placeholder copy) stay unbound (fixed in place, rule added to the build scripts) |
| 9 | `in set_minWidth: Can only set minWidth on auto layout nodes and their children` | `minWidth` set on a text node before it was appended to its auto-layout parent | Append first, then set `minWidth` / `layoutSizing*`. A failed `use_figma` call is rolled back as a whole (verified: no orphans), so the fixed script can simply be re-run |
| 10 | ▶ ◀ rendered as blue emoji tiles in Figma | Glyphs with an emoji presentation (U+25B6, U+25C0) are not in Fredoka; Figma falls back to its emoji font while Chrome uses a text symbol font | Replace such glyphs with SVG vectors (`createNodeFromSvg`) whose fill is bound to the colour variable. ➜ ✕ ✓ → × render fine as text |
| 11 | Proportional segment widths (`flex-grow: n`) not reproducible | Figma `layoutGrow` only accepts 0 or 1 | Compute proportional fixed widths in the build script (save share bar) |
| 12 | Turn banner missing from its reference capture | animejs drives the banner with an inline transform and parks it off-screen; the director's greet timer also clears `banner` after 1.4 s | Scenario pins the state: CSS `transform: none !important` + a guard that ignores `banner: null` while capturing (`scenarios.mjs`). Rule: timer- or animation-driven UI must be pinned in the fixture |
| 13 | **`use_figma` → "You've reached the Figma MCP tool call limit on the Starter plan"** after ~20 calls | Starter plan / View seat: ~20 MCP tool calls per month, and `use_figma` writes count too (only `create_new_file`, `whoami`, `generate_figma_design`, `add_code_connect_map` are exempt) | Pipeline no longer depends on the MCP quota: every build script also runs in the local **Code → Figma runner** plugin (`scripts/figma/runner-plugin`), which has no call limit. Alternatively a Professional plan with a Dev/Full seat (200 calls/day) — that also lifts issues 4 and 5 |
| 14 | Runner: `07-setup` failed with only `at run (PLUGIN_3_SOURCE:451:94)` | `isExposedInstance` set on an instance before it was nested in a component; the plugin sandbox's `e.stack` has no message line | Set `isExposedInstance` after appending. Runner now reports `e.message` + stack |
| 15 | Runner: `cannot read property 'createInstance' of undefined` | A screen asked for a variant (`Kind=Human, State=Locked`) that the set never created | Player row is now the full Kind × State matrix; `I()` throws `variant "…" not found in <set>` |
| 16 | Runner: `in get_mainComponent: Cannot call with documentAccess: dynamic-page` | The MCP runtime tolerates the sync `instance.mainComponent` getter; a real dynamic-page plugin does not | Screen + verify scripts use `getMainComponentAsync()` via `setOf()` / `instancesOf()` in `_screens.js`. Rule: no sync getters for cross-node lookups |
| 17 | Validation: tablet / short / mobile screens scored 8–15% MAD | The one 1440×900 board raster was cropped into every viewport; the real app re-frames the 3D camera | `capture.mjs --backdrop` renders the scene with the UI hidden per viewport + context (game / idle); the runner embeds them and `screen()` picks the right one (`14-fixes.js` patches existing screens) |
| 18 | "Panel open" icon button showed a soft glow instead of a 3px pink ring; die / swatch rings faint | Figma ignores drop-shadow `spread` on frames that do not clip content | Ring = 3px OUTSIDE stroke (icon button); `clipsContent = true` where nothing overflows (die, swatch) |
| 19 | Curtain gradient elliptical, card 40px high | Radial gradient transform guessed; CSS is `circle at 50% 40%` farthest-corner | Transform derived from geometry: `[[0.8,0,0.1],[0,0.5,0.3]]` for 1440×900; card centred |
| 20 | Screens showed placeholder data (save rows, odds 92%, log order) | Library defaults ≠ scenario fixture | Save rows / odds now carry the fixture values; log fixture fixed to oldest-first so the panel shows newest-first. Rule: screens use the same data as `scenarios.mjs` |
| 21 | Validation pass 2: tablet must-trade, tablet help, mobile saves / setup still over budget | Viewport-dependent CSS not modelled: `left: 50%` shrink-to-fit makes the hand bar wrap at 1024px; help modal `max-height: 100vh − 60`; mobile saves is an in-game state with a growing save button; mobile setup card is centred | `15-responsive.js` patch: hand bar `layoutWrap`, `Card hand ▸ Must trade (narrow)`, help capped + clipped, mobile saves with HUD, centred setup (ported to 04/08/12) |
| 22 | Validation pass 3: "Start game" left-aligned in Figma; input placeholder wrapping to two lines | Start row excluded from FILL; Figma text wraps where a native input clips | `16-setup-inputs.js`: start rows FILL + centred; input text `maxLines 1` + ellipsis (ported to 02/07) |
| 8 | `textStyleId` / `effectStyleId` assignment throws in `use_figma` | The MCP runs plugins with `documentAccess: dynamic-page` | Always use `setTextStyleIdAsync`, `setEffectStyleIdAsync`, `setFillStyleIdAsync` (`_lib.js`) |
